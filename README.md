# PROF_2027

Единая мультиагентная система для конкурсного задания «Машинное обучение и большие данные» (компетенция «Профессионалы»).

Проект объединяет:

- **`mish`** — каркас мультиагентной системы, БД, дашборд, API, отчёты, тесты, сборка;
- **`sava`** — AI-ядро: OCR, классификация учебных материалов, аннотации.

## Статус

- **Этап 0 — каркас** — завершён: конфиг, каталоги YAML, 8 таблиц БД, CLI (`init`/`status`/`requirements reload`), единый фильтр входных файлов, пользователи дашборда.
- **Этап 1 — загрузчик (модуль А)** — завершён: конвейер discover → validate → hash → dedup → copy → parse → classify → moderate → save; AI-адаптеры (`indra-ocr`, `d1-2B`, `LaciaSUM`); парсеры всех форматов; manifest; markdown-отчёт; 61 тест.
- Далее: этап 2 — датасет и признаки, этап 3 — кластеризация.

## Идея системы

Система **универсальная**: работает с любыми учебными материалами — школа, СПО, вуз, курсы, дополнительное образование. Уровень образования (`school` / `spo` / `university` / `unknown`) — это **атрибут материала**, а не отдельный режим работы. Каталоги предметов, типы материалов, типы занятий и методические требования — редактируемые YAML-файлы; классификатор сам подхватывает изменения.

## Целевые возможности

- загрузка материалов по ссылкам и из папок, дедупликация, версионирование;
- фильтрация входящих файлов: белый список расширений, проверка сигнатуры, лимиты размера, карантин;
- OCR PDF/сканов, разбор DOCX/PPTX/HTML, анализ изображений и видео;
- классификация одним вызовом d1-2B: категория, дисциплина, тема, уровень образования, язык (`ru`/`en`/`other`), тип материала, тип занятия, сложность, соответствие методическим требованиям;
- аннотирование (LaciaSUM), модерация, генерация недостающих материалов;
- датасет, анализ признаков, prev/next-связи;
- кластеризация: параллельное изучение (материалы из разных предметов), последовательное изучение (внутри предмета по возрастанию сложности), сложность;
- обучение и сравнение ML-моделей, контроль дрейфа, версионирование;
- оценка времени и построение индивидуальных траекторий;
- интерактивный дашборд с ролями;
- REST API;
- Telegram-бот (polling, публичный; токен пока не задан);
- отчёты по модулям, комплексная документация, демонстрация ≤10 минут;
- офлайн-запуск агентов без установки зависимостей.

## Модели

Все модели — локальные, из `sava`, лежат в `models/`:

| Модель | Назначение | Размер |
|---|---|---:|
| `indra-ocr` (ONNX) | OCR PDF/сканов/изображений | ~50 МБ |
| `d1-2B` (LiquidAI) | классификация и модерация | ~3,6 ГБ |
| `LaciaSUM v1` | аннотации | ~850 МБ |

Генеративная LLM не используется: генерация материалов — шаблонно-retrieval по ближайшим материалам.

## Запуск

```bash
prof2027 init
prof2027 loader run --source C:\Users\sava\Desktop\ms\dop_test_1   # папка целиком
prof2027 loader run --source data/incoming/demo_manifest.txt --limit 10 --skip-ai
prof2027 loader run --source data/incoming/ai_demo_manifest.txt    # полный AI-цикл
prof2027 dataset build
prof2027 cluster run --strategy all
prof2027 train run --task all
prof2027 continuous check
prof2027 predict time --scope material
prof2027 predict trajectory --input user.yaml
prof2027 dashboard
prof2027 api
prof2027 bot
prof2027 report all
```

Ключевые флаги `loader run`:

- `--source` — папка с материалами **или** manifest (`.txt` — путь на строку, `.json` — список);
- `--limit N` — обработать первые N файлов;
- `--max-pages N` — максимум страниц для извлечения текста (по умолчанию 20);
- `--skip-ai` — только парсинг, без d1-2B/LaciaSUM (классификация пропускается, вердикт `pending`);
- `--no-ocr` — не загружать `indra-ocr` (для сканов и изображений);
- `--hint TEXT` — подсказка классификатору.

Результат загрузки — `reports/loader_report_*.md`, копии файлов — в `data/raw/`.

### Как работает классификация (d1-2B)

- **Проход 1** — категория (9 из каталога), уровень образования, язык, тип материала, тип занятия, сложность (5 уровней), тема;
- **Проход 2** — дисциплина: только из предметов выбранной категории (точнее, чем 35 вариантов сразу);
- **Модерация** — один вызов по 24 методическим требованиям (multiple-choice), вердикт по порогам из `config.yaml` (`approved ≥ 0.7`, `needs_review ≥ 0.4`, иначе `rejected`).

Атрибуты, для которых уверенность ниже порога, сохраняются как неопределённые (категория `< 0.4`, дисциплина `< 0.3`) — система не записывает неверные ярлыки.
