# PROF_2027 — поэтапный план разработки

Каждый этап заканчивается рабочим результатом и проверкой. Следующий этап не начинается, пока предыдущий не принят.

Система универсальная: уровень образования — атрибут материала, отдельных школьного и вузовского режимов нет.

---

## Этап 0. Каркас и контракты

**Результат:**

- структура проекта;
- конфиг и `.env.example`;
- SQLAlchemy-модели (8 таблиц);
- каталоги: `subjects.yaml`, `methodology.yaml`, `material_types.yaml`, `class_types.yaml`, `languages.yaml`;
- CLI;
- инициализация БД;
- пользователи дашборда;
- базовые тесты.

**Проверка:**

- `prof2027 init` создаёт БД и каталоги;
- `prof2027 --help` работает;
- логин/пароль печатаются в консоли;
- тесты проходят.

---

## Этап 1. AI-адаптеры и загрузчик (модуль А)

**Результат:**
- адаптеры OCR (`indra-ocr`), классификатора (`d1-2B`), суммаризатора (`LaciaSUM`);
- единый валидатор входных файлов: белый список расширений, сигнатура, лимиты размера, карантин;
- парсинг PDF/DOCX/PPTX/HTML/EPUB/FB2/TXT/изображений/аудио/видео;
- manifest (txt/json);
- дедупликация по SHA-256 (поле `source_hash`);
- классификация: категория (проход 1), дисциплина по предметам категории (проход 2), уровень образования, язык, тип материала, тип занятия, сложность 1–5, тема;
- аннотация (LaciaSUM + экстрактивный fallback);
- модерация по 24 требованиям (multiple-choice) с порогами из `config.yaml`;
- отчёт ingestion (markdown).

**Проверка (выполнено):**
- 61 тест зелёный (включая pipeline с фейковыми адаптерами, dedup, manifest, отчёт);
- модели d1-2B / LaciaSUM / indra-ocr загружаются из `models/` офлайн;
- демо-прогон по 5 реальным файлам `dop_test_1` → `reports/loader_report_*.md`;
- повторный запуск не создаёт дублей;
- переименованный `.exe` → `.pdf` и `~$...docx` отклоняются по сигнатуре;
- обрезанный EPUB читается по локальным zip-записям;
- PNG с расширением `.jpg` принимается (безопасный растровый формат).

## Этап 2. Датасет и признаки (модуль А)

**Результат:**

- `dataset.csv` / `dataset.parquet`;
- признаки текста, медиа, модерации, сложности, TF-IDF/SVD;
- важность признаков;
- prev/next (внутри предмета — по возрастанию сложности);
- описание атрибутов;
- графики.

**Проверка:**

- датасет содержит все обязательные поля;
- описание есть по каждому атрибуту;
- графики строятся;
- prev/next корректны на золотом наборе.

---

## Этап 3. Кластеризация (модуль Б)

**Результат:**

- 3 стратегии: параллельное (разные предметы), последовательное (внутри предмета), сложность;
- сравнение KMeans / Agglomerative / GMM / DBSCAN;
- метрики качества (silhouette, CH, DB, стабильность);
- t-SNE;
- метки в БД;
- отчёт.

**Проверка:**

- метки сохраняются;
- метрики считаются;
- визуализации строятся;
- вывод обоснован.

---

## Этап 4. Обучение и непрерывное обучение (модуль В)

**Результат:**

- 3 задачи: параллельность, последовательность, сложность;
- ≥3 алгоритма на задачу;
- метрики и сравнение;
- сохранение моделей и версий;
- дрейф (KS, chi-square, PSI) и переобучение;
- отчёт.

**Проверка:**

- ROC-AUC считается;
- лучшая модель выбирается;
- версии логируются;
- дрейф обнаруживается на синтетическом сдвиге;
- нет утечки: признаки и целевые метки разведены, GroupKFold по предметам.

---

## Этап 5. Время и траектории (модуль В)

**Результат:**

- траектория по параметрам пользователя;

- время считается для всех уровней;
- траектория учитывает дедлайн и часы/день;
- Gantt строится.
