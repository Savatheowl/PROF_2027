# PROF_2027 — архитектура

Версия: 1.0 (утверждена 2026-11-08)

---

## 1. Идея (30 секунд)

Одна универсальная мультиагентная система работает с **любыми учебными материалами** — школа, СПО, вуз.
Уровень образования (`school`/`spo`/`university`/`unknown`) — **атрибут материала**, а не режим.
Всё настраивается данными в `config/*.yaml`, код не трогаем. Работает **офлайн**.

## 2. Пять модулей задания

| Модуль | Баллы | Что даём |
|---|---|---:|---|
| А. Сбор и обработка | 22 | загрузка, OCR, классификация, аннотация, модерация, датасет, признаки, prev/next, генерация, отчёт |
| Б. Анализ и визуализация | 20,5 | дашборд (роли, 10 вкладок), 3 стратегии кластеризации, метрики, отчёт |
| В. Моделирование | 19 | 3 задачи × ≥3 алгоритма, метрики, непрерывное обучение, дрейф, время, траектории, отчёт |
| Г. Интеграция | 18 | REST API (Swagger), Telegram-бот, документация |
| Д. Демонстрация | 20,5 | отчёты, README, PyInstaller `--onedir`, демо ≤10 мин без интернета |

## 3. Принципы

1. Универсальность — один каркас для школы/СПО/вуза.
2. Каталоги и требования — YAML-данные, классификатор подхватывает сам.
3. Никакого rule-based LLM: только модели из `sava`.
4. Простая БД — **8 таблиц**.
5. Учебных планов нет: внутри предмета сортировка **по сложности**, параллельность — **между предметами**.
6. Повторный запуск не создаёт дублей (хеш + URL).
7. Офлайн: модели локальные, интернет на демо не нужен.
8. Единый фильтр входа: расширение + сигнатура + размер.
9. ML без утечки: признаки ≠ метки, GroupKFold по предметам.
10. Каждый шаг коммитится в git, всё откатываемо.

## 4. Агенты

| Агент | Что делает |
|---|---|
| `agent_loader` | загрузка, фильтр, OCR, классификация, аннотация, модерация |
| `agent_dataset` | датасет, признаки, важность, prev/next, описание |
| `agent_generator` | пробелы → генерация по ближайшим материалам |
| `agent_clusterer` | параллельно / последовательно / сложность |
| `agent_trainer` | обучение и сравнение моделей |
| `agent_continuous` | дрейф и переобучение |
| `agent_predictor` | время и траектории |
| `agent_dashboard` | Dash-интерфейс |
| `agent_api` | REST API |
| `agent_telegram` | Telegram-бот (polling) |

Агенты общаются через БД и файлы; CLI/API/дашборд/бот используют общий сервисный слой.

## 5. Модель данных — 8 таблиц

| Таблица | Назначение |
|---|---|
| `subjects` | категория → дисциплина |
| `materials` | материал + признаки + метки кластеров + prev/next + время |
| `methodological_requirements` | требования (из YAML) |
| `material_compliance` | материал × требование → score + evidence |
| `cluster_runs` | запуски кластеризации + метрики |
| `model_versions` | модели + метрики + дрейф + версии |
| `users` | доступы к дашборду |
| `trajectories` | вход/выход траекторий |

Медиа — JSON в `materials`. Метки кластеров — поля `cluster_parallel`, `cluster_sequential`, `complexity_level`.

## 6. Пайплайн (одна команда на шаг)

```
init                    → БД, каталоги, требования, пользователи
loader run              → загрузка → классификация → аннотация → модерация
dataset build           → признаки → prev/next → важность → описание
cluster run --strategy all
train run --task all    → 3 задачи × ≥3 алгоритма
continuous check        → дрейф (KS / chi-square / PSI) → переобучение
predict time / trajectory
dashboard / api / bot
report all
```

## 7. Классификация (один вызов d1-2B)

категория → дисциплина → тема → уровень образования → язык (`ru`/`en`/`other`) → тип материала → тип занятия → сложность 1–5 → соответствие каждому требованию.

## 8. Кластеризация

| Стратегия | Логика |
|---|---|
| Параллельное | материалы из **разных предметов**, близкая сложность/объём |
| Последовательное | **внутри предмета** по возрастанию сложности |
| Сложность | 5 уровней по текстовым признакам |

Сравнение: KMeans / Agglomerative / GMM / DBSCAN. Метрики: silhouette, CH, DB, стабильность (ARI), t-SNE.

## 9. ML

Задачи: параллельность, последовательность, сложность. ≥3 алгоритма. Метрики: Accuracy/Precision/Recall/F1/ROC-AUC. Валидация: holdout 20% + GroupKFold по предметам. Сохранение: joblib + `model_versions`.

## 10. AI-слой (все из `sava`, локальные)

| Модель | Роль | Размер |
|---|---:|---|
| `d1-2B` (LiquidAI) | классификация, модерация | ~3,6 ГБ |
| `LaciaSUM v1` | аннотации | ~850 МБ |
| `indra-ocr` (ONNX) | OCR | ~50 МБ |
| TF-IDF + SVD | семантика, кластеры, prev/next | 0 МБ |

Генерация — шаблонно-retrieval (генеративной LLM нет).

## 11. Конфигурация

`config/config.yaml` + каталоги: `subjects.yaml`, `methodology.yaml`, `material_types.yaml`, `class_types.yaml`, `languages.yaml`.

`.env`: пути, пароли дашборда, Telegram-токен (пустой), API-ключ, `HF_HUB_OFFLINE=1`, `TRANSFORMERS_OFFLINE=1`.

## 12. Доступы к дашборду

```
admin / admin
analyst / analyst
viewer / viewer
```

Печатаются в консоли при запуске и указаны в README.

## 13. Фильтр входа (единый: CLI, API, бот)

Белый список: PDF, DOCX/DOC, PPTX/PPT, RTF, TXT/MD, HTML/HTM, PNG/JPG/JPEG/WebP/BMP/TIFF, MP4/MOV/AVI/MKV. Проверки: расширение → сигнатура (magic bytes) → размер (100 МБ/файл, 500 МБ/видео). Неподходящий — пропуск с причиной в отчёте; подозрительный — карантин.

## 14. Модерация

24 требования (8 категорий × 3). Вердикт: `approved ≥ 0.7`, `needs_review ≥ 0.4`, `rejected < 0.4`.

## 15. Утверждённые решения

1. Каталог — 9 категорий, ~30 дисциплин, дополняется автоматически.
2. Сложность — 5 уровней.
3. Семантика — TF-IDF + SVD.
4. Генерация — по ближайшим материалам.
5. Telegram — polling, публичный, токен в `.env`.
6. Сборка — `--onedir` + `models/`.
7. Пароль админа — `admin/admin`.
8. Фильтр входа — единый валидатор.
9. Git — коммит каждого шага.
10. Модели — реальные копии из `sava` в `models/` (не ссылки).
