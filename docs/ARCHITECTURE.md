# PROF_2027 — архитектура системы

Версия: **1.0** · статус: согласована · дата: 2026-11-08

---

## 1. Идея в пяти строках

1. Это **одна универсальная система** для любых учебных материалов: школа, СПО, вуз, курсы.
2. Уровень образования — **атрибут материала**, а не режим работы.
3. Каталоги предметов и методические требования — **редактируемые YAML**, классификатор сам подхватывает.
4. Всё AI-ядро — **модели из `sava`**: OCR, d1-2B, LaciaSUM. Никаких rule-based «моделей».
5. Один сквозной pipeline: **загрузка → датасет → кластеризация → обучение → прогноз → сервисы + отчёты**.

## 3. Принципы

1. **Универсальность.** Один набор правил для всех уровней образования.
2. **Настройка данными.** `config/*.yaml` → классификатор строит вопросы сам, код не трогаем.
3. **ML без утечки.** Признаки и целевые метки разведены, GroupKFold по предметам.
4. **Офлайн.** На демо интернет не нужен: модели, БД, артефакты — локальные.
5. **Без дублей.** SHA-256 + URL; повторный запуск ничего не копирует.
6. **Каждый агент — исполняемый модуль.** Плюс единый pipeline для демо.

## 4. Предметная область

### 4.1 Предметы: категория → дисциплина

`config/subjects.yaml` — 9 категорий, ~30 дисциплин.

```yaml
categories:
  - name: "Программирование и компьютеры"
    subjects: ["Разработка искусственного интеллекта", "Информационные системы", "Базы данных"]
```

Дисциплина вне каталога добавляется автоматически (`source=auto`).

## 5. Методические требования

`config/methodology.yaml` — **8 категорий × 3 требования = 24**.

```yaml
- category: "Научная достоверность"
  requirements: ["Отсутствие фактических ошибок", "Корректность терминологии", "Актуальность информации"]
```

Замена набора = положить новый YAML → перезапуск. Классификатор строит вопросы динамически.

## 7. Сквозной сценарий

```
1. loader      → файлы/URL → фильтр → OCR → классификация d1-2B → аннотация → модерация → БД
2. dataset     → признаки, prev/next (по сложности), важность, описание, графики
3. cluster     → параллельно (разные предметы) / последовательно (внутри предмета) / сложность
4. train       → 3 задачи × ≥3 алгоритма + метрики + версии; continuous: дрейф → переобучение
5. predict     → время, траектории (с учётом сложности и параллельности)
6. serve       → dashboard / api / bot / report
```

CLI:

```bash
prof2027 init
prof2027 loader run --manifest data/incoming/manifest.yaml
prof2027 dataset build
prof2027 cluster run --strategy all
prof2027 train run --task all
prof2027 continuous check
prof2027 predict time --scope material
prof2027 predict trajectory --input user.yaml
prof2027 dashboard
prof2027 api
prof2027 bot
prof2027 report all
```

### 7.1 Фильтрация входных файлов

Один валидатор для loader, API и бота (`core/validation.py`):

1. **Расширение** в белом списке:

   | Группа | Расширения |
   |---|---|
   | Документы | `.pdf`, `.docx`, `.doc`, `.pptx`, `.ppt`, `.rtf`, `.txt`, `.md` |
   | Веб | `.html`, `.htm` |
   | Изображения | `.png`, `.jpg`, `.jpeg`, `.webp`, `.bmp`, `.tiff` |
   | Видео | `.mp4`, `.mov`, `.avi`, `.mkv` |

2. **Сигнатура** (magic bytes) совпадает с расширением — переименованный `.exe` уходит в карантин.
3. **Размер**: 100 МБ на файл, 500 МБ на видео, 2 ГБ за запуск.

Неподходящий файл **пропускается с причиной**, запуск не падает; отчёт показывает принято/пропущено/отклонено.

## 8. AI-слой

| Компонент | Что | Fallback |
|---|---|---|
| OCR | `indra-ocr` (ONNX) | PyMuPDF |
| Классификация | `d1-2B`: категория, дисциплина, тема, уровень, язык, тип, занятие, сложность, 24 требования | нет |
| Аннотация | `LaciaSUM` | первые предложения |
| Семантика | TF-IDF + SVD (без e5) | — |
| Генерация | шаблонно-retrieval по ближайшим материалам | — |

Модели лежат в `models/` (скопированы из `sava`):

```
models/
├─ model_classifier/   # d1-2B, ~3,6 ГБ
├─ anotation-model/    # LaciaSUM, ~0,85 ГБ
└─ ocr_model/          # indra-ocr, ~0,1 ГБ
```

## 10. Конфигурация и сборка

```
config/
├─ config.yaml        # пути, лимиты, параметры ML
├─ subjects.yaml      # категории и дисциплины
├─ methodology.yaml   # 24 требования
└─ material_types.yaml, class_types.yaml, languages.yaml
```

`.env`: доступы, Telegram-токен (пустой), API-ключ, `HF_HUB_OFFLINE=1`, `TRANSFORMERS_OFFLINE=1`.

Сборка: PyInstaller `--onedir` на каждый агент + лаунчер, папка `models/` в комплекте, офлайн-флаги. Демо ≤10 минут без интернета.

## 11. Утверждённые решения

1. Каталог категорий/дисциплин — базовый из `subjects.yaml`, дополняется вручную.
2. Методические требования — 8×3 из `sava`, легко заменяются YAML.
3. Модерация: `approved ≥ 0.7`, `needs_review ≥ 0.4`, `rejected < 0.4`.
4. Сложность — 5 уровней.
5. Генерация — шаблонно-retrieval, без LLM.
6. Семантика — TF-IDF + SVD, без e5.
7. Уровень образования — атрибут (`school`/`spo`/`university`/`unknown`).
8. Сортировка по сложности внутри предмета; параллельность — между предметами.
9. Фильтр входа: белый список + сигнатура + размер, карантин для подозрительных.
10. Дашборд: логин/пароль, admin/admin.
11. Telegram: polling, публичный, токен в `.env` (сейчас пустой).
12. Сборка: PyInstaller `--onedir` + `models/`.
13. Модели — скопированы из `sava`, не симлинки.
