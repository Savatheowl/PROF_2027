# PROF_2027 — какие данные и примеры нужны

Документ описывает, что требуется от заказчика, в каком формате и с каким приоритетом.

Система универсальная: данные могут быть по школе, СПО или вузу — уровень образования хранится как атрибут материала, а не как отдельный режим.

Приоритеты:

- **P0** — без этого нельзя начать и проверить ключевые модули;
- **P1** — нужно до финальной сборки и демонстрации;
- **P2** — улучшения качества.

---

## 1. P0 — блокирующие данные

### 1.1 Источники материалов

Нужно:

1. **Ссылки из конкурсного задания** (или manifest), по которым агент должен загружать материалы.
2. **20–50 реальных файлов**, если ссылки недоступны.

Форматы (белый список; остальное система отфильтрует):

| Группа | Расширения |
|---|---|
| Документы | `.pdf`, `.docx`, `.doc`, `.pptx`, `.ppt`, `.rtf`, `.txt`, `.md` |
| Веб | `.html`, `.htm` |
| Книги (электронные) | `.epub`, `.fb2` |
| Изображения | `.png`, `.jpg`, `.jpeg`, `.webp`, `.bmp`, `.tiff` |
| Видео | `.mp4`, `.mov`, `.avi`, `.mkv` |
| Аудио | `.mp3` |

Ограничения по умолчанию: до 100 МБ на файл, до 500 МБ на видео/аудио, до 8 ГБ за запуск. Архивы (`.zip`) автоматически не распаковываются.

Файлы с правильным расширением, но неверной сигнатурой (например, переименованный `.exe`), уходят в карантин и в отчёт — пайплайн при этом не падает.

Для каждого файла желательно знать (не обязательно, классификатор определит сам):

- уровень образования (`school` / `spo` / `university`);
- категорию и дисциплину;
- тему;
- тип материала;
- тип занятия.

Формат manifest:

```yaml
sources:
  - url: "https://..."
    education_level: university
    category: "Программирование и компьютеры"
    subject: "Разработка искусственного интеллекта"
    topic: "Нейронные сети"
    material_type: student_material
    class_type: lecture

  - path: "data/incoming/physics_lecture_01.pdf"
    education_level: school
    category: "Естественные науки"
    subject: "Физика"
    topic: "Кинематика"
    material_type: student_material
    class_type: lesson
```

Подсказки не обязательны: система определит автоматически. Но для валидации нужны эталонные ответы.

### 1.2 Методические требования

По умолчанию используем **8 категорий × 3 требования** из `sava` (24 требования), они уже зафиксированы в `config/methodology.yaml`.

Нужно одно из двух:

1. **Подтвердить** этот набор — тогда ничего дополнительно не требуется;
2. **Дать свои требования** — официальные методические рекомендации, ФГОС, РПД, критерии оценивания (PDF/DOCX/CSV/XLSX). Мы заменим YAML, классификатор сам построит вопросы.

Формат замены:

```yaml
- category: "Научная достоверность и актуальность"
  requirements:
    - "Отсутствие фактических ошибок"
    - "Корректность терминологии"
    - "Актуальность информации и источников"
```

### 1.3 Каталог категорий и дисциплин

Базовый каталог уже есть в `config/subjects.yaml` (9 категорий, ~30 дисциплин).

Нужно:

- **подтвердить** список;
- **дополнить** своими дисциплинами, если чего-то не хватает.

Формат:

```yaml
categories:
  - name: "Программирование и компьютеры"
    subjects:
      - "Разработка искусственного интеллекта"
      - "Информационные системы"
```

Дисциплины, которых нет в каталоге, классификатор добавляет автоматически с пометкой `source=auto`.

### 1.4 Последовательности материалов

Учебных планов не требуется. Внутри предмета материалы сортируются **по возрастанию сложности**, параллельное изучение — материалы из **разных предметов**.

Но для проверки логики нужны эталонные данные:

- для 2–3 предметов — список материалов в правильном порядке (от простого к сложному);
- 20–50 экспертных пар «можно изучать параллельно» (разные предметы, близкая сложность);
- 20–50 экспертных пар «это продолжение» (внутри предмета).

Формат:

```yaml
subject: "Физика"
order:
  - material_id: 3
  - material_id: 7
  - material_id: 12

pairs:
  - material_a: 3
    material_b: 15
    relation: parallel
    comment: "Разные предметы, независимые темы"
  - material_a: 3
    material_b: 7
    relation: sequential
    comment: "Продолжение темы"
```

Без этого система работает, но качество кластеризации и траекторий нельзя проверить.

### 1.5 Золотой набор размеченных материалов

**30–50 материалов** с эталонными полями:

| Поле | Пример |
|---|---|
| id | 1 |
| education_level | university |
| category | Программирование и компьютеры |
| subject | Разработка искусственного интеллекта |
| topic | Нейронные сети |
| language | ru |
| material_type | student_material |
| class_type | lecture |
| complexity | 1–5 |
| compliance по требованиям | 0 / 0.5 / 1 |
| verdict | approved / needs_review / rejected |
| prev_id / next_id | 5 / 7 |
| parallel_with | [12, 15] |
| sequential_with | [7] |

Формат: XLSX/CSV/YAML.

Нужно для:

- проверки классификатора;
- проверки модерации;
- обучения и оценки моделей;
- демонстрации качества.

### 1.6 Нормы времени

Нужны экспертные оценки:

- сколько минут занимает изучение материала (по сложности и объёму);
- сколько времени на практику/тест;
- сколько времени на тему;
- сколько времени на предмет.

Формат: CSV/XLSX.

```csv
material_id,minutes
1,25
2,40
3,15
```

Если нет — используем формулу и откалибруем позже.

### 1.7 Telegram

- токен бота (в `.env`, не в репозитории);
- username бота;
- Telegram ID администраторов.

Сейчас токен не задаём: поля в `.env` уже есть, бот запускается только при заполненном токене.

### 1.8 Оборудование

- целевая ОС (Windows 10/11?);
- CPU/GPU;
- RAM;
- свободное место на диске;
- будет ли интернет на демонстрации;
- допустим ли запуск с папкой моделей ~4,5 ГБ.

## 2. P1 — до финальной сборки

### 2.1 Примеры хороших и плохих материалов

- 5–10 материалов, которые эксперт считает образцовыми;
- 5–10 материалов, которые должны быть отклонены.

Нужно для настройки порогов модерации.

### 2.2 Пользователи дашборда

- нужны ли дополнительные логины помимо `admin` / `analyst` / `viewer`;
- роли и права.

### 2.3 Брендинг

- полное название конкурса;
- регион;
- год;
- логотип (если есть);
- требования к титульному листу отчётов.

---

## 3. P2 — улучшения

- исторические данные о времени изучения;
- дополнительные корпуса материалов;
- примеры сгенерированных материалов, которые нравятся эксперту;
- пожелания по стилю интерфейса;
- ограничения по размеру поставки;
- генеративная LLM для более естественной генерации (сейчас не используется).

---

## 4. Что можно не давать

- персональные данные;
- закрытые материалы без прав на использование;
- токены и пароли в открытом виде (только в `.env` или защищённом канале).

---

## 5. Минимальный стартовый комплект

Если времени мало, достаточно:

1. 10–20 файлов разных форматов (PDF, DOCX, PPTX, изображения, 2–3 видео);
2. подтверждение каталога категорий и дисциплин;
3. подтверждение 24 методических требований (или свои);
4. 30 размеченных материалов;
5. 20–50 экспертных пар «параллельно / последовательно»;
6. нормы времени хотя бы по 10 материалам;
7. информация о железе.

Этого хватит, чтобы пройти весь цикл и показать демонстрацию, а качество наращивать постепенно.
